# Свои Финансы — агро-приложение: расчёт норм кормления

Flutter-сервис расчёта норм кормления **КРС, МРС, свиней и птицы** с учётом возраста, веса, продуктивности и условий содержания, а также **годовой потребности хозяйства в кормах** (в тоннах и рублях). Реализован полностью на тестовых данных **без бэкенда**.

> Полное описание аудиторий, сценариев использования и трёх концепций — в [`docs/CONCEPTS.md`](docs/CONCEPTS.md).

## 2. Модель расчёта норм кормления

Суточная потребность в кормовых единицах (КЕ):

```
КЕ_сут = (КЕ_поддержки × K_молодняка + КЕ_продукции) × K_условий
```

**Поддержание жизни** (по живой массе):

| Вид | Формула |
|---|---|
| КРС | `0.02 × вес + 1.5` |
| МРС | `0.04 × вес + 0.3` |
| Свиньи | `0.03 × вес + 0.4` |
| Птица | `0.11 + 0.002 × вес особи` |

**Продуктивная часть**: молоко — `0.45 КЕ/л`; привес — `0.5 КЕ/кг`; яйца — `0.02 КЕ/шт`.

**Возраст**: молодняк (≤ 6 мес.) — поддержка × **1.15**, продукция не учитывается.

**Условия содержания** (коэффициент): стойловое 1.00, пастбищное 0.95, смешанное 0.98, клеточное (птица) 1.05.

**Раскладка рациона**: суточные КЕ делятся по категориям кормов (для высокопродуктивных коров доля концентратов до 55%, у птицы грубые корма исключены), каждая доля пересчитывается в кг через КЕ/кг representative-корма из каталога.

**Годовая потребность хозяйства**: `Σ(суточные кг каждого корма × headCount) × 365 дней`, стоимость — через цену ₽/т из справочника.

Все формулы покрыты unit-тестами (`test/feeding_service_test.dart`).

## 3. Экраны (9 макетов)

| # | Экран | Файл | Описание |
|---|---|---|---|
| 1 | Вход | `login_screen.dart` | Форма e-mail/пароль с валидацией, градиентный фон |
| 2 | PIN-код | `pin_screen.dart` | Клавиатура 0–9, индикаторы, демо-PIN `1234`, обработка ошибки |
| 3 | Главный | `home_screen.dart` | Сводка: поголовье, кг/сут, КЕ/сут, ₽/год; быстрые действия |
| 4 | Список животных | `animals_screen.dart` | Карточки с нормой КЕ, фильтр-чипы по видам |
| 5 | Детали животного | `animal_detail_screen.dart` | Параметры + таблица раскладки рациона (корм/доля/кг/КЕ) |
| 6 | Добавление животного | `add_animal_screen.dart` | Форма с валидацией: вид, возраст, вес, продуктивность, содержание |
| 7 | Каталог кормов | `feed_catalog_screen.dart` | DataTable справочника питательности (12 кормов) |
| 8 | Годовая потребность | `annual_need_screen.dart` | Итоги по кормам: т/год и тыс. ₽, кнопка «список закупки» (демо) |
| 9 | Профиль | `profile_screen.dart` | Хозяйство, владелец, настройки PIN, выход |

**Навигация**: `MaterialApp` с именованными маршрутами (`main.dart`) → `LoginScreen → /pin → /main`. Оболочка `MainShell` — нижняя панель `NavigationBar` из 5 вкладок (`Home / Животные / Год / Каталог / Профиль`) через `IndexedStack`; детали животного и форма добавления открываются push-маршрутами.

## 4. Установка и запуск

### Требования

- **Flutter SDK ≥ 3.22** (Dart ≥ 3.4) — проверено на Flutter 3.24.5
- Любой целевой платформенный toolchain: Chrome (web), Android SDK (эмулятор/устройство), Xcode (iOS), либо десктоп

### Шаги

```bash
# 1. Проверить окружение
flutter doctor

# 2. Перейти в папку приложения и скачать зависимости
cd app
flutter pub get

# 3. Запуск (выберите один вариант)
flutter run -d chrome            # веб (быстрее всего для демо)
flutter run -d emulator-5554     # эмулятор Android
flutter run                      # первое доступное устройство
```

### Демо-доступ

| Шаг | Значение |
|---|---|
| Экран входа | любой e-mail с `@`, пароль ≥ 4 символов (валидация клиентская) |
| PIN-код | **`1234`** (подсказка по кнопке «Забыли?») |

Данные хранятся только в памяти процесса: после перезапуска приложение возвращается к 10 тестовым записям поголовья КФХ «Заря».

### Сборка релиза (опционально)

```bash
flutter build web --release      # build/web/
flutter build apk --release      # build/app/outputs/flutter-apk/app-release.apk
```

## 6. Как расширять до боевого варианта

1. Заменить `data/farm_data.dart` на репозиторий с REST/SQLite (`Repository`-интерфейс уже изолирован в `AppState`).
2. В `FeedingService` подставить нормы из НСО Рамзай / ОКС вместо упрощённых формул — API методов стабилен.
3. Добавить экспорт годовой потребности в CSV/XLSX на экране №8.
4. Подключить локальное хранилище (`shared_preferences`) для PIN и поголовья между сессиями.
